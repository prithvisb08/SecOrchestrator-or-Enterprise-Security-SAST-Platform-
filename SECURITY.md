# Security Policy

## Supported Versions

SecOrchestrator takes the security of our platform and the code it scans seriously. Only the latest major release branch receives security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

If you believe you have discovered a vulnerability in SecOrchestrator itself, please **do not open a public issue or discussion**.

Instead, report it privately via GitHub Security Advisories or by emailing:
**security@secorchestrator.internal**

Please include:
1. A clear description of the vulnerability (e.g., path traversal, unauthenticated access, denial of service).
2. Steps to reproduce or proof-of-concept (PoC) code.
3. Impact assessment and affected components/endpoints.

### Disclosure Process

- **Acknowledgment**: Within 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days.
- **Fix & Advisory**: Fixes will be prepared, verified against test suites, and released with a CVE identifier and advisory.
